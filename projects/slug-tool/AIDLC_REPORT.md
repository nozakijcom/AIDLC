## 設計上の判断とその理由

Kiro の design.md を正とし、上書きせず以下の実装レベルの判断のみを補いました。

1. **「ASCIIに変換できない文字は削除ではなく区切り」の実装方法** — `encode("ascii", "ignore")` を使わず、NFKD 分解後に1文字ずつ走査し、(a) 結合文字（`unicodedata.combining(c)` が真）は削除、(b) 非ASCII文字は `-` に置換、(c) それ以外は保持、としました。`encode(..., "ignore")` では AC5（アクセント除去）と AC6（非ラテン文字を区切り扱い）を同時に満たせません（前者は結合文字を落としたい、後者は文字を落とさず区切りにしたい）。この2つの要求は「結合文字か否か」でのみ区別できるため、分類を明示しています。design.md が指摘する「単に削除すると `abcdef` になる」問題への具体解です。

2. **`None` チェックを `isinstance` チェックより前に置く** — `None` は `str` でないため順序を逆にすると AC8 が `TypeError` になり AC9 と衝突します。`ValueError` と `TypeError` に継承関係がないことを明示するテストを置き、将来のリファクタでこの順序が壊れても検知できるようにしました。

3. **`isinstance(text, str)` による型判定（ダックタイピングを採用しない）** — AC9 が型エラーを要求しているため明示的判定とし、結果として `str` サブクラス（`enum.StrEnum` 等）は受理されます。これはリスコフの置換原則に沿った意図的な許容で、テストで固定しました。`bool` は `int` のサブクラスなので `TypeError` になることもテストで明示しています。

4. **正規表現をモジュールレベルで事前コンパイル（`_NON_ALNUM_RUN`）** — 呼び出しごとの再コンパイルを避けます。`re` の内部キャッシュに頼らず、パターンが単一箇所に集約されることで安全性レビュー（ReDoS 監査）も容易になります。

5. **末尾処理に `strip("-")` を使用** — 置換後の文字集合が `[a-z0-9-]` に限定されているため、正規表現による先頭/末尾アンカー処理より単純かつ高速で、AC7（結果が空になる場合）も分岐なしで自然に `""` を返します。

6. **純粋関数・ゼロ依存を維持** — I/O も可変状態も持たないため、design.md の「モックは不要」というテスト方針がそのまま成立し、同一入力に対する結果の安定性・冪等性をテストで固定しました。Clean Architecture 上、`slugkit.slugify` は外側の層へ一切依存しない最内層のドメインロジックとして閉じています。

7. **成果物を仕様記載の3ファイル＋`tests/__init__.py` に限定** — `pyproject.toml`、`README`、`Makefile`、品質ゲートツール類は今回の requirements.md / tasks.md に含まれないため作成していません（「仕様にない機能・ツール・ドキュメントは作らない」ルールに準拠）。`tests/__init__.py` のみ、`unittest discover` でのパッケージ解決とパッケージ名衝突回避のために追加した最小の構成ファイルです。

8. **カバレッジ検証は使い捨てのインラインスクリプトで実施** — `trace` 実行は標準入力経由のワンショットで行い、計測ツールをリポジトリに残していません（スコープ外のツール追加を避けるため）。再現コマンドは本報告に記載済みです。
